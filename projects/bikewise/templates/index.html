Three models. One chronological split. No test-set tuning.

Validation chooses. Test evaluates.

Each candidate is first fitted on the training period. The lowest validation MAE selects the winner. Models are then refitted on train + validation before this final test comparison.

Keep the future unseen

Training transformations are fitted inside each pipeline. Early stopping is disabled to avoid an internal random validation split.

What the scores mean

MAE · mean absolute error
Average size of a prediction error, in bikes per hour. Lower is better.
RMSE · root mean squared error
Gives larger errors more weight. Lower is better.
R² · coefficient of determination
Compares squared error with a mean-target reference on the test data. It is not a percentage accuracy and can be negative.

What this project does not prove

The data comes from one bike-sharing system in 2011–2012. Performance here does not establish accuracy for present-day cities. Test inputs include recorded weather; a real future forecast would need weather forecasts available at prediction time. Extreme weather has very few examples. These estimates are for learning and scenario exploration.

Leakage prevented: casual and registered add up to the target cnt, so they never enter the model. The row identifier and raw date are also excluded from features.

UNDERSTAND IT. THEN PRESENT IT.

Learn the project.

An AI & Data Science walkthrough you can explain in class.

01 / PROBLEM

Predict a quantity

The question is: how many bike rentals might happen in one hour? The answer is a number, so this is regression, not classification.

02 / DATA

Turn observations into features

Each row is one recorded hour. Inputs include hour, month, working-day status, weather, temperature, humidity and wind. The target is total rental count.

03 / PREPARATION

Keep the experiment fair

Sort by time, separate past from future, encode categories and scale numerical inputs. Fit preprocessing only on the current training split.

04 / LEARNING

Compare a simple starting point

The mean baseline predicts one average. Ridge learns weighted relationships. Gradient boosting combines small trees that improve earlier predictions.

05 / EVALUATION

Measure unseen performance

Choose using validation MAE. Evaluate once on the held-out test period. Report MAE, RMSE and R² alongside the dates and limitations.

06 / APPLICATION

Put the model to work

The browser sends scenario inputs to Flask. The server validates them, applies the trained pipeline, and returns a count and a 24-hour curve.
